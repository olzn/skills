# Skills

Independently installable single skills.

## Available Skills

- [`grill-with-docs`](grill-with-docs/) - Grill a plan against the domain model and sharpen terminology into CONTEXT.md and ADRs before design. Derived from Matt Pocock's MIT-licensed [skills](https://github.com/mattpocock/skills).
- [`prototype`](prototype/) - Generate N different HTML implementations of a UI feature, preview them in a gallery, and iterate. Quietly flags a favourite; does not pick, research, or ship.
- [`logic-prototype`](logic-prototype/) - Single-file HTML demo that answers whether a state model, business logic, or data shape feels right; a pure liftable module a non-developer can drive. Derived from Matt Pocock's MIT-licensed [skills](https://github.com/mattpocock/skills).
- [`paper-prototype`](paper-prototype/) - Create Paper-first UI prototype directions before committing to implementation.
- [`pre-build-review`](pre-build-review/) - Red-team a settled plan before coding and decide whether it is ready to build.
- [`build`](build/) - Take a scoped request or chosen direction to a verified candidate ready for the owner's local review, bracketed by the two reviews and fingerprinted for tamper-evident handoff. Never self-ships.
- [`post-build-review`](post-build-review/) - Check a built change against its intent and promised states, then assemble the handoff evidence. The read-only mirror of `pre-build-review`.
- [`wrapup`](wrapup/) - Close out a feature worktree once its PR has merged: teardown with ownership, merge, and clean-state guards, plus an `--abandon` mode.
- [`polish-fix`](polish-fix/) - Land one small UI papercut as a tiny, easy-to-approve PR with a before/after screenshot.
- [`decision-coach`](decision-coach/) - Coach a real decision, or stress-test reasoning you've already formed, routing by stakes and reversibility onto a fast, middle, or deep path. Explicitly invoked.
- [`handoff`](handoff/) - Compact the current conversation into a Markdown handoff another session or agent can resume from, saved to a durable, harness-agnostic path. Captures state and next steps, not a transcript.
- [`harness-config`](harness-config/) - Keep agent configuration aligned across more than one harness from a single canonical source with generated per-harness projections.
- [`writing-for-agents`](writing-for-agents/) - Reference for writing any document an agent consumes: context pointers, the two loads, information hierarchy, completion criteria, leading words, and pruning. Adapted from Matt Pocock's MIT-licensed [skills](https://github.com/mattpocock/skills).
